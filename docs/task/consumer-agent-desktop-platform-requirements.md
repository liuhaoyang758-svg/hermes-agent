# C 端个人 Agent 桌面工作台需求文档

## 1. 项目背景

原 B 端垂直行业 Agent SaaS 平台面向企业、服务商和团队，核心是多租户、行业模板、业务流程配置、Skill 编排、数据源连接、员工赋能和经营分析。

如果转换为 C 端产品，产品不应再强调“企业级 Agent 搭建平台”，而应转向“个人开箱即用的 AI Agent 工作台”。它要帮助个人用户把日常资料、表格、聊天记录、待办事项和业务场景交给 Agent 处理，让用户用一句话完成过去需要打开多个软件、查表、复制粘贴、手动整理和设置提醒的操作。

本产品优先面向有明确业务场景、资料处理需求和高频沟通需求的个人用户，例如跨境电商物流销售、房产经纪人、教育老师、课程顾问、保险代理人、自由职业者、本地生活商家、个体电商卖家和私域运营人员。

## 2. 产品定位

本产品定位为：

> 面向个人职业场景的 AI Agent 桌面工作台。

它不是企业后台，不是单纯聊天机器人，也不是纯知识库问答工具，而是一个能够理解个人上下文、读取个人资料、判断当前意图、选择合适 Skill，并输出可执行结果的桌面端 AI 助手。

核心目标：

- 用户用一句话表达需求，Agent 自动识别意图和场景。
- Agent 能读取用户上传的文档、Excel、报价表、排班表、课程表、客户记录等资料。
- Agent 能从对话或粘贴文本中抽取时间、地点、人物、货物、预算、课程、客户需求等关键信息。
- Agent 能选择合适 Skill 执行动作，例如查报价、查排班、生成回复、创建提醒、生成便利贴、整理客户档案。
- 桌面端能提供快捷呼出、剪贴板识别、便利贴、系统通知、本地文件拖拽等 C 端高频体验。
- 如果后续增加 APP 端，桌面和手机可以同步待办、提醒、客户信息和 AI 处理结果。

## 3. 从 B 端到 C 端的核心变化

| 维度 | B 端 Agent SaaS | C 端个人 Agent 工作台 |
|---|---|---|
| 目标用户 | 企业、服务商、团队 | 个人销售、老师、顾问、自由职业者、个体商家 |
| 产品目标 | 企业搭建和运营 Agent | 个人少操作、快处理、自动提醒、辅助决策 |
| 使用方式 | 管理员配置，员工使用 | 个人开箱即用，边用边沉淀资料和模板 |
| 组织结构 | 多租户、部门、角色、权限 | 个人账号、个人空间、可选家庭/小团队空间 |
| 行业模板 | 企业级行业模板 | 个人场景模板 |
| Skill 编排 | 管理员配置复杂流程 | 系统内置 Skill，用户可轻量自定义 |
| 数据源 | CRM、ERP、数据库、企业系统 | 本地文件、Excel、聊天记录、日历、通讯录、网页链接 |
| 工作流 | 企业流程自动化 | 个人任务自动化和提醒 |
| 计费方式 | 企业套餐、席位、用量 | 免费额度、会员订阅、AI 点数、专业场景包 |
| 核心体验 | 可配置、可管控、可评估 | 一句话、少点击、即时结果、桌面提醒 |

## 4. 目标用户

### 4.1 第一优先级用户

#### 跨境电商物流销售人员

典型资料：报价表、渠道规则、附加费表、国家分区、货物限制、客户聊天记录。

典型问题：

- “客户有 20kg 的货物要寄到美国，选哪个渠道？”
- “这个客户觉得贵，帮我生成一个更容易成交的回复。”
- “这批货带电池，能不能走空派？”
- “根据报价表给客户生成报价说明。”
- “帮我记录这个客户下周三再跟进。”

#### 教育老师 / 培训机构老师 / 私教

典型资料：排班表、课程表、学生名单、课件、家长沟通记录。

典型问题：

- “我 6 月 7 号有课吗？”
- “明天下午我有哪些学生？”
- “帮我给家长生成一段课后反馈。”
- “这个学生最近缺课几次？”
- “下周需要提醒哪些学生续费？”

#### 个人销售 / 顾问

典型资料：客户资料、产品介绍、价格表、聊天记录、跟进记录。

典型问题：

- “这个客户现在意向高吗？”
- “帮我生成下一句回复。”
- “客户说太贵了，怎么回复？”
- “帮我把这段聊天整理成客户档案。”
- “明天下午 3 点提醒我约见客户。”

### 4.2 第二优先级用户

- 房产经纪人：房源匹配、带看提醒、贷款测算、客户跟进。
- 保险代理人：方案解释、异议处理、客户生日/续保提醒。
- 电商卖家：客服回复、售后处理、商品标题、差评回复。
- 自媒体/自由职业者：选题、内容计划、客户需求整理、交付提醒。
- 本地生活商家：预约排班、会员回访、活动话术、评价回复。
- 体制内工作人员：事业单位、公务员、基层工作人员、窗口人员、学校/医院/科研院所行政人员，用于办文、办会、办事、查政策、做台账、盯截止时间和整理材料。

## 5. 产品核心原则

- 场景优先：不是让用户配置 Agent，而是让用户直接选择或触发场景。
- 一句话触发：用户自然语言输入即可触发查表、提醒、总结、推荐、生成等动作。
- 资料即能力：用户上传报价表、排班表、课程表后，Agent 就能基于资料回答和执行。
- 桌面即入口：支持快捷键呼出、拖拽上传、剪贴板识别、便利贴和系统通知。
- 人控优先：涉及发送消息、客户沟通、重要业务动作时，默认由用户确认。
- 可解释结果：Agent 输出答案时说明依据来自哪个文件、哪张表、哪个字段或哪段记录。
- 隐私优先：用户明确授权后才读取剪贴板、日历、通知、文件和通讯录。

## 6. 核心业务抽象模型

### 6.1 用户空间

每个用户拥有一个默认个人空间，用于存放资料、Agent 记忆、客户、待办、模板和设置。

后续可扩展小团队空间，例如夫妻店、小工作室、2-5 人销售小组，但 MVP 以个人空间为主。

### 6.2 场景模板

场景模板是面向个人用户的预置能力集合，例如：

- 跨境物流报价助手。
- 教师排班查询助手。
- 客户聊天意图识别助手。
- 客户跟进提醒助手。
- 销售异议处理助手。
- 文件问答助手。
- 便利贴待办助手。
- 课后反馈生成助手。
- 机关事业单位办公助手。

### 6.3 Skill 技能

Skill 是 Agent 可调用的原子能力。C 端不直接向用户暴露“Skill”概念，而是在产品里包装为“场景能力”。

常见 Skill：

- 表格查询 Skill：读取 Excel/CSV，查找符合条件的行和字段。
- 规则匹配 Skill：根据重量、国家、货物属性、时间等规则匹配最佳方案。
- 文档问答 Skill：基于 PDF、Word、TXT、网页回答问题。
- 文本意图识别 Skill：识别粘贴文字中的事项、时间、地点、联系人和动作。
- 待办提醒 Skill：创建桌面便利贴、系统提醒和手机提醒。
- 客户画像 Skill：从聊天记录抽取需求、预算、意向、阶段、标签。
- 回复生成 Skill：根据上下文和个人资料生成沟通话术。
- 日程查询 Skill：查询用户日历、排班表和课程表。
- 总结归档 Skill：把聊天、会议、课程反馈整理成结构化记录。
- 公文材料 Skill：根据用户资料生成通知、请示、报告、纪要、总结、方案和提纲。
- 政策制度查询 Skill：基于政策文件、制度汇编、办事指南回答问题，并标注出处。
- 督办催办 Skill：从通知、会议纪要、领导交办事项中提取责任人、截止时间和待办。

### 6.4 个人资料库

个人资料库是用户上传和授权连接的数据集合，包括：

- PDF、Word、Markdown、TXT。
- Excel、CSV、报价表、课程表、排班表。
- 图片和截图，后续可做 OCR。
- 手动粘贴的聊天记录。
- 网页链接和收藏内容。
- 政策文件、制度汇编、通知公告、公文模板、会议纪要、台账表格、值班表和办事指南。
- 本地文件夹，后续支持增量同步。
- 日历、通讯录、邮件，后续用户授权接入。

### 6.5 Agent

Agent 是面向个人用户的 AI 助手。它通过对话上下文、用户输入、当前应用环境、剪贴板内容、资料库和历史记录判断当前场景，然后选择合适 Skill 执行动作。

Agent 的核心流程：

1. 接收用户输入或系统触发事件。
2. 识别用户意图和业务场景。
3. 判断是否需要读取资料、查表、检索、计算、创建提醒或生成回复。
4. 选择合适 Skill。
5. 执行 Skill 并生成结构化结果。
6. 如果涉及重要动作，等待用户确认。
7. 保存记录，并在需要时创建便利贴、待办或手机提醒。

## 7. 核心功能需求

### 7.1 账号与个人空间

- 支持手机号、邮箱、微信扫码登录。
- 支持个人资料、职业身份、默认行业和常用场景设置。
- 支持多设备登录，桌面端和 APP 端同步数据。
- 支持个人数据导出和一键删除。
- 支持会员等级、AI 用量、文件容量和功能权限。

### 7.2 桌面快捷入口

- 支持全局快捷键呼出 Agent，例如 Ctrl + Shift + A。
- 支持悬浮球或菜单栏快捷入口。
- 支持右键菜单：选中文本后“交给 AI 处理”。
- 支持拖拽文件到桌面端窗口自动上传分析。
- 支持系统托盘后台运行。
- 支持开机自启，可由用户关闭。

### 7.3 剪贴板意图识别

用户复制或粘贴一段文字后，Agent 可以识别其中的意图。

示例：

用户粘贴：

> 明天下午 3 点需要约见客户，地点在京海市北航大道咖啡店。

Agent 自动识别：

- 事件类型：约见客户。
- 时间：明天下午 3 点。
- 地点：京海市北航大道咖啡店。
- 动作：创建提醒。
- 展示方式：桌面便利贴 + 系统通知。
- 如果存在 APP：同步手机推送。

用户粘贴客户聊天记录时，Agent 自动识别：

- 是否是客户咨询。
- 客户需求是什么。
- 客户是否有购买意向。
- 是否需要报价、推荐方案或约时间。
- 是否需要创建客户档案或跟进提醒。

### 7.4 个人资料上传与解析

- 支持上传 PDF、Word、TXT、Markdown、Excel、CSV。
- 支持拖拽上传。
- 支持自动识别文件类型和用途，例如报价表、排班表、课程表、产品资料、合同模板。
- 支持 Excel 表头识别、字段类型推断、单位识别。
- 支持多 Sheet 表格解析。
- 支持用户手动修正字段含义。
- 支持文件版本管理，避免旧报价表和新报价表混用。
- 支持按文件、文件夹、标签和场景管理资料。

### 7.5 表格查询与规则匹配

Agent 需要能根据用户问题自动从表格中查找答案，并在必要时执行规则匹配和计算。

#### 跨境物流示例

用户上传物料：

- 报价表。
- 国家分区表。
- 渠道限制表。
- 附加费规则。
- 货物属性规则。

用户提问：

> 用户有 20kg 的货物要寄到美国，选哪个？

Agent 处理流程：

1. 识别行业场景：跨境物流报价/渠道推荐。
2. 提取关键参数：目的国=美国，重量=20kg。
3. 判断是否缺少参数，例如体积、货物属性、是否带电、时效要求。
4. 如果资料足够，读取报价表和渠道规则。
5. 按价格、时效、限制、利润或用户偏好进行匹配。
6. 输出推荐渠道、价格区间、时效、推荐理由和备选方案。
7. 生成可复制给客户的报价话术。

Agent 输出示例：

- 推荐渠道：美国空派专线 A。
- 依据：20kg 在报价表第 X 档，美国属于 Y 分区，该渠道支持普货。
- 预计时效：7-10 天。
- 参考报价：按报价表计算。
- 备选渠道：经济渠道 B，价格更低但时效更慢。
- 需要补充确认：是否带电、是否液体、体积尺寸。

#### 教师排班示例

用户上传物料：

- 6 月课程表。
- 老师排班表。
- 学生名单。

用户提问：

> 我 6 月 7 号有课吗？

Agent 处理流程：

1. 识别场景：排班查询。
2. 确认当前用户身份，例如老师姓名。
3. 查询排班表中 6 月 7 号对应课程。
4. 输出课程时间、课程名称、学生、教室或线上会议链接。
5. 如果有课，询问是否需要创建上课提醒。
6. 如果无课，说明当天暂无排班。

### 7.6 桌面便利贴与提醒

- 支持从自然语言自动创建便利贴。
- 支持便利贴固定在桌面上。
- 支持设置提醒时间。
- 支持提醒前 5 分钟、15 分钟、1 小时等自定义通知。
- 支持便利贴颜色、优先级、标签。
- 支持把便利贴转换为待办。
- 支持待办完成、推迟、删除、重复提醒。
- 支持与系统日历同步，后续支持手机日历同步。

典型输入：

- “明天下午 3 点约见客户，地点在京海市北航大道咖啡店。”
- “周五提醒我给王总发报价。”
- “下个月 1 号提醒我续费服务器。”
- “今晚 8 点提醒我给学生发课后反馈。”

### 7.7 客户聊天识别与销售副驾

用户可以粘贴客户聊天记录，Agent 自动识别：

- 客户身份。
- 客户需求。
- 预算或价格敏感度。
- 时间要求。
- 异议点。
- 当前阶段。
- 下一步动作。

可执行动作：

- 生成下一句回复。
- 生成报价话术。
- 生成异议处理话术。
- 创建客户档案。
- 创建跟进提醒。
- 标记高意向客户。
- 生成沟通复盘。

### 7.8 个人轻量 CRM

- 支持从聊天记录中一键生成客户档案。
- 支持记录姓名、联系方式、来源、需求、预算、阶段、标签、备注。
- 支持客户阶段：新咨询、已报价、待回复、待跟进、已成交、已流失。
- 支持客户时间线，记录每次沟通、AI 建议、用户操作和跟进结果。
- 支持高意向客户提醒。
- 支持漏跟提醒。
- 支持 CSV/Excel 导入导出。

### 7.9 场景助手中心

内置多个个人场景助手：

#### 跨境物流报价助手

- 查国家分区。
- 查重量价格档。
- 匹配渠道。
- 识别货物限制。
- 生成报价话术。
- 生成备选方案。

#### 教师排班助手

- 查询某日是否有课。
- 查询某学生课程安排。
- 生成课后反馈。
- 生成家长沟通话术。
- 创建上课提醒。

#### 客户跟进助手

- 识别跟进时间。
- 创建待办。
- 生成跟进话术。
- 提醒未回复客户。
- 复盘跟进效果。

#### 文件问答助手

- 基于个人资料库回答问题。
- 引用来源。
- 总结文档。
- 对比多个文件。
- 提取表格重点。

#### 个人日程助手

- 从自然语言创建日程。
- 查询今天/明天/本周安排。
- 提醒会议、课程、客户拜访。
- 与 APP 端同步提醒。

#### 文案和回复助手

- 生成客户回复。
- 改写语气。
- 多语言翻译。
- 生成朋友圈/小红书/邮件文案。
- 根据个人资料保持专业表达。

#### 机关事业单位办公助手

- 查政策、查制度、查办事指南。
- 生成通知、请示、报告、方案、总结、会议纪要和工作简报初稿。
- 从来文、通知、会议纪要中提取事项、责任人、截止时间和材料要求。
- 根据台账、值班表、人员名单、预算表做自然语言查询和统计。
- 自动生成督办清单、便利贴和到期提醒。
- 将零散材料汇总成结构化提纲、表格或汇报稿。
- 对群众咨询、窗口办事问题生成规范答复草稿。
- 对敏感内容启用本地优先、脱敏、引用来源和人工确认。

### 7.10 APP 端联动能力

如果增加 APP 端，APP 不必承载复杂配置，重点做移动提醒和快速处理。

APP 端核心能力：

- 手机推送提醒。
- 查看桌面端创建的便利贴和待办。
- 快速语音输入任务。
- 拍照上传资料。
- 查看客户档案。
- 查看今日跟进。
- 接收 AI 分析结果。
- 移动端复制文字后分享给 Agent 处理。

桌面端与 APP 端同步：

- 账号数据同步。
- 文件处理结果同步。
- 待办和便利贴同步。
- 客户档案同步。
- AI 会话同步。
- 会员和用量同步。

### 7.11 体制内 / 事业单位 / 公务员办公场景

体制内用户的高频痛点不是“不会写字”，而是每天需要在大量通知、政策、表格、会议、台账、材料和截止时间之间切换。Agent 的价值是减少查找、整理、复制、填表、提醒和初稿生成的重复劳动，让个人办公更稳、更快、更不漏事。

#### 7.11.1 典型用户角色

- 综合办公室人员：办文、办会、材料汇总、通知发布、督办跟进。
- 业务科室人员：政策执行、材料报送、台账维护、数据统计、群众咨询答复。
- 基层工作人员：网格、社区、乡镇街道、窗口服务、日常报表和通知落实。
- 学校/医院/科研院所行政人员：排班、会议、采购、资产、人事、培训和资料归档。
- 党建、人事、财务、采购、资产管理人员：制度查询、流程提醒、材料清单和节点跟踪。

#### 7.11.2 办文场景

用户上传资料：

- 历史通知、请示、报告、工作总结、会议纪要。
- 单位公文模板、格式规范、领导常用表达。
- 上级文件、政策依据、年度重点工作安排。

典型问题：

- “根据这个活动安排，帮我写一份会议通知。”
- “把这段文字改成更正式的公文表达。”
- “根据这几份材料，生成一份工作汇报提纲。”
- “帮我把会议记录整理成会议纪要。”
- “这份报告有哪些表述不够规范？”

Agent 可执行动作：

- 生成公文初稿、标题、提纲、正文和附件清单。
- 按“通知、请示、报告、函、纪要、方案、总结、简报”识别文种。
- 根据上传模板套用单位格式和常用结构。
- 自动补齐背景、依据、目标、安排、要求、联系人等常见模块。
- 标注引用来源，避免无依据编造政策。
- 输出“可直接复制版”和“需人工确认项”。

#### 7.11.3 办会场景

典型问题：

- “下周要开安全生产会议，帮我列会议准备清单。”
- “根据这段会议录音转写，生成会议纪要和任务分工。”
- “把这次会议涉及的待办事项生成便利贴提醒。”
- “帮我写一条会议通知，要求各科室负责人参加。”

Agent 可执行动作：

- 生成会议通知、议程、主持词、签到表、材料清单。
- 从会议纪要中提取责任单位、责任人、截止时间和交付材料。
- 自动生成督办清单。
- 将关键截止时间同步为桌面便利贴和 APP 提醒。
- 会后生成简报、纪要、任务分解表和复盘清单。

#### 7.11.4 办事和窗口服务场景

用户上传资料：

- 办事指南、材料清单、政策问答、窗口常见问题、服务流程。

典型问题：

- “群众问办理这个事项需要哪些材料，怎么回复？”
- “这项业务的办理条件是什么？”
- “根据办事指南，帮我生成一段窗口标准答复。”
- “这类事项是哪个科室负责？”

Agent 可执行动作：

- 根据办事指南生成标准答复草稿。
- 输出办理条件、材料清单、办理时限、责任部门和注意事项。
- 对群众提问进行意图识别，匹配对应事项。
- 对缺失材料生成补正告知清单。
- 对不确定问题提示“需要人工核实”，不直接给确定结论。

#### 7.11.5 政策制度查询场景

典型问题：

- “这个补贴政策适用条件是什么？”
- “文件里关于报销标准是怎么规定的？”
- “某类人员能不能参加这个项目？”
- “把这几个政策文件的差异对比一下。”

Agent 可执行动作：

- 基于上传政策文件做问答。
- 显示引用来源，例如文件名、章节、条款、页码。
- 对多个政策文件做差异对比。
- 将政策要求转换为执行清单。
- 将复杂条款翻译成易懂表达。
- 对过期文件、冲突条款提示风险。

#### 7.11.6 台账、报表和值班排班场景

体制内用户大量时间消耗在 Excel 台账和报表上，这类场景非常适合做成“表格查询 + 统计 + 提醒”Skill。

典型问题：

- “这个月哪些单位还没报材料？”
- “下周谁值班？”
- “6 月 7 号谁在岗？”
- “统计一下各科室本季度活动数量。”
- “把这张表里即将到期的事项找出来。”

Agent 可执行动作：

- 读取台账、值班表、人员名单、预算表、项目进度表。
- 按日期、科室、人员、状态、金额、事项类型进行查询。
- 自动生成统计摘要、透视结果和异常提醒。
- 识别临近截止、未完成、未报送、重复记录和缺失字段。
- 将关键事项生成便利贴、待办和手机提醒。

#### 7.11.7 督办催办和截止时间管理

典型输入：

> 请各单位于 6 月 15 日前报送安全检查自查表，联系人张某，邮箱 xxx。

Agent 自动识别：

- 事项：报送安全检查自查表。
- 截止时间：6 月 15 日。
- 对象：各单位。
- 联系人：张某。
- 交付物：自查表。
- 动作：创建督办待办、便利贴和提前提醒。

可执行动作：

- 从通知、来文、会议纪要中自动抽取待办。
- 生成个人督办台账。
- 到期前提醒用户催办。
- 生成催办话术，例如“请尚未报送的单位于今日下班前反馈”。
- 对已完成、未完成、延期事项做状态管理。

#### 7.11.8 党建、学习和培训场景

典型问题：

- “根据这个主题，帮我生成一份学习计划。”
- “把这篇材料整理成学习笔记。”
- “生成一份主题党日活动方案初稿。”
- “帮我把学习内容整理成简报。”

Agent 可执行动作：

- 生成学习计划、活动方案、简报初稿。
- 汇总学习材料重点。
- 生成会议记录和心得提纲。
- 根据活动安排生成物料清单和时间节点提醒。

#### 7.11.9 能让体制内用户离不开的核心 Skill

| Skill | 高频价值 | 典型输出 |
|---|---|---|
| 来文要点提取 Skill | 快速看懂通知和上级文件 | 事项、责任人、截止时间、材料要求 |
| 政策引用问答 Skill | 减少翻文件时间 | 答案 + 文件出处 + 条款依据 |
| 公文初稿 Skill | 降低材料起草时间 | 通知、请示、报告、纪要、总结初稿 |
| 会议纪要 Skill | 会后快速沉淀任务 | 纪要、任务分工、督办清单 |
| 台账统计 Skill | 减少 Excel 查找和统计 | 未报送名单、到期事项、统计摘要 |
| 督办提醒 Skill | 防止漏办、迟报、忘报 | 桌面便利贴、待办、APP 推送 |
| 材料汇总 Skill | 多部门材料快速合并 | 汇总稿、差异点、缺失项清单 |
| 窗口答复 Skill | 提高群众咨询回复效率 | 标准答复、材料清单、办理流程 |
| 格式规范 Skill | 减少公文格式和表达问题 | 修改建议、规范化版本 |

#### 7.11.10 体制内场景的边界和合规要求

- 涉密文件、内部敏感文件、未公开政策不得上传到公有云模型。
- 产品需要提供“本地优先处理”“私有化模型”“敏感信息脱敏”能力作为后续高级版本。
- Agent 只能生成草稿、提取信息、辅助查询和提醒，不能代替用户作出行政决定。
- 政策答复必须展示依据来源，不能无出处编造。
- 对不确定、冲突、过期政策必须提示人工核实。
- 涉及人事、财务、采购、执法、审批等高风险场景，必须增加人工确认和权限提示。

#### 7.11.11 体制内用户的粘性来源

- 每天都有通知、表格、会议、材料和截止时间，使用频率高。
- 查政策、翻文件、找依据非常耗时，Agent 能直接给出处。
- 办文办会存在固定格式和套路，Agent 能持续复用个人模板。
- 督办催办不能漏，桌面便利贴和手机提醒能形成刚需。
- 台账和报表重复劳动多，自然语言查表能明显节省时间。
- 用户越用，个人资料库、模板和常用表达越完整，迁移成本越高。

## 8. Agent 意图识别与 Skill 路由

### 8.1 意图分类

Agent 需要支持以下意图类型：

- 查询类：查表、查课程、查报价、查资料。
- 推荐类：推荐渠道、推荐课程、推荐方案、推荐回复。
- 生成类：生成话术、反馈、总结、文案、邮件。
- 提取类：从文本中提取时间、地点、人物、金额、货物、需求。
- 提醒类：创建便利贴、待办、日程和手机提醒。
- 归档类：创建客户档案、保存沟通记录、整理资料。
- 决策类：比较多个方案，给出最佳选择和理由。
- 追问类：信息不足时主动询问缺失字段。
- 办文办会办事类：生成公文初稿、会议材料、办事答复和任务分解。
- 政策制度类：查询政策、对比制度、提取依据和生成执行清单。
- 督办催办类：从通知和纪要中提取截止时间、责任人和报送要求。

### 8.2 Skill 路由策略

MVP 阶段建议采用“规则 + LLM + 资料上下文”的混合路由方式。

路由流程：

1. 识别用户输入中的关键词、时间、地点、数量、单位、行业词。
2. 判断当前上下文，例如当前打开文件、最近上传资料、用户职业身份。
3. 使用 LLM 输出结构化意图。
4. 根据意图选择候选 Skill。
5. 检查 Skill 是否需要资料、权限或补充信息。
6. 执行 Skill。
7. 输出结果和下一步建议。

### 8.3 结构化输出要求

Agent 内部输出应尽量结构化，便于前端渲染不同 UI。

示例字段：

- intent：意图。
- scenario：场景。
- entities：实体信息。
- missing_fields：缺失字段。
- selected_skill：选中的 Skill。
- action_type：回复、查询、提醒、便利贴、客户档案、日程。
- result：结果。
- evidence：依据来源。
- suggested_next_actions：下一步建议。
- need_user_confirm：是否需要用户确认。

## 9. 桌面端 UI 设计建议

### 9.1 主窗口

- 左侧：场景助手、资料库、客户、待办、历史会话。
- 中间：Agent 对话窗口。
- 右侧：上下文面板，展示当前文件、客户、待办、引用来源和推荐动作。

### 9.2 快捷弹窗

- 通过快捷键呼出。
- 适合快速输入一句话。
- 支持粘贴文字后自动识别。
- 结果可以一键复制、一键保存、一键创建提醒。

### 9.3 便利贴 UI

- 轻量悬浮卡片。
- 支持显示时间、地点、联系人和事项。
- 支持置顶、收起、完成、推迟。

### 9.4 文件处理页

- 展示已上传资料。

## 10. 非功能需求

### 10.1 隐私与安全

- 剪贴板读取必须用户授权。
- 文件上传必须用户主动操作。
- 用户可以删除文件、会话、客户和待办。
- AI 调用前对敏感信息做可选脱敏。
- 不将用户数据用于模型训练，除非用户明确授权。
- 支持本地缓存加密。
- 服务端存储敏感字段加密。

### 10.2 稳定性

- 文件解析失败需要提示原因。
- Agent 工具调用失败需要降级为普通问答或请求用户补充。
- 提醒服务需要本地和云端双保险。
- 桌面端离线时，待办和便利贴仍可查看。
- 网络恢复后自动同步。

### 10.3 可解释性

- 查表结果需要展示引用来源。
- 推荐结果需要说明推荐理由。
- 信息不足时不能乱猜，需要主动追问。
- 高风险操作需要用户确认。

### 10.4 可扩展性

- 场景助手插件化。
- Skill 可独立升级。
- 文件解析器可扩展。
- 模型供应商可切换。
- 桌面端和 APP 端共享同一套后端 API。

## 12. 技术架构

### 12.1 推荐总体架构

采用“桌面端 + 云端 API + Agent 服务 + 数据服务”的架构。

```text
Electron 桌面端
  ├─ React UI
  ├─ 快捷键/托盘/通知/便利贴
  ├─ 本地缓存 SQLite
  ├─ 文件拖拽与本地预处理
  └─ WebSocket 实时同步

        ↓ HTTPS / WebSocket

后端 API 服务
  ├─ 用户账号
  ├─ 会员与用量
  ├─ 资料库管理
  ├─ 客户和待办
  ├─ 文件上传
  ├─ Agent 会话
  └─ 多端同步

        ↓

Agent 服务
  ├─ 意图识别
  ├─ Skill 路由
  ├─ 表格查询
  ├─ RAG 检索
  ├─ 工具调用
  ├─ 结构化输出
  └─ 执行日志

        ↓

基础设施
  ├─ PostgreSQL
  ├─ pgvector
  ├─ Redis
  ├─ MinIO / OSS
  ├─ 消息队列
  └─ 模型供应商
```

### 12.2 你熟悉技术栈下的推荐选型

考虑你熟练 Python、Electron、React、Java、Spring 全套技术栈，推荐两种落地方案。

#### 方案 A：Python AI 优先，开发速度最快

| 模块 | 技术选型 |
|---|---|
| 桌面端 | Electron + React + TypeScript + Vite |
| UI 组件 | Ant Design / Arco Design |
| 状态管理 | Zustand |
| 请求缓存 | TanStack Query |
| 桌面能力 | electron-builder、electron-updater |
| 本地缓存 | SQLite |
| 后端 API | FastAPI |
| Agent 服务 | FastAPI + LangGraph/自研轻量编排 |
| 表格处理 | pandas、openpyxl |
| 文档解析 | unstructured、python-docx、pypdf、markitdown |
| 向量检索 | PostgreSQL + pgvector |
| 数据库 | PostgreSQL |
| 缓存队列 | Redis + Celery/RQ |
| 文件存储 | MinIO / 阿里云 OSS |
| 部署 | Docker Compose |

适合：MVP 快速验证、AI 能力迭代快、团队 Python 能力强。

#### 方案 B：Java 主业务 + Python Agent，长期更稳

| 模块 | 技术选型 |
|---|---|
| 桌面端 | Electron + React + TypeScript + Vite |
| 主业务后端 | Spring Boot 3 |
| 权限认证 | Spring Security + JWT |
| 数据访问 | MyBatis Plus / Spring Data JPA |
| Agent 服务 | Python FastAPI |
| 异步任务 | Redis + Celery / Spring Scheduler |
| 数据库 | PostgreSQL + pgvector |
| 文件存储 | MinIO / OSS |
| 实时通信 | WebSocket / SSE |
| 部署 | Docker Compose / Kubernetes 后置 |

适合：后期要做会员、支付、运营后台、多端同步和更复杂业务稳定性。

### 12.3 推荐最终选择

MVP 阶段建议选择：

> Electron + React + TypeScript + FastAPI + PostgreSQL + pgvector + Redis + MinIO

原因：

- 你熟悉 Electron 和 React，桌面端可以快速开发。
- Python 做 Agent、表格处理、文档解析最方便。
- PostgreSQL + pgvector 足够支撑个人资料库和向量检索。
- FastAPI 同时承载 API 和 Agent 服务，MVP 架构简单。
- 后续用户量上来，再把会员、支付、账号和运营后台拆到 Spring Boot。

## 13. Agent 技术实现建议

### 13.1 不建议一开始重度依赖通用 Agent 平台

MVP 不建议把核心能力完全建立在 Dify、Coze 或 LangChain Agent 黑盒之上。

建议自研轻量 Agent Runtime，重点做好：

- 意图识别。
- Skill 注册。
- Skill 路由。
- 工具调用。
- 结构化输出。
- 执行日志。
- 引用来源。

可以借鉴 LangGraph 的状态机思想，但核心业务模型建议自己控制。

### 13.2 Skill 接口设计

每个 Skill 建议包含：

- skill_code：唯一编码。
- name：名称。
- description：描述。
- input_schema：输入参数。
- output_schema：输出结构。
- required_sources：需要的数据源类型。
- handler：执行函数。
- confidence_threshold：置信度阈值。
- need_confirm：是否需要用户确认。

### 13.3 表格查询实现

表格类文件不能只做向量检索，需要结构化解析。

建议流程：

1. 上传 Excel/CSV。
2. 解析 Sheet、表头、字段类型和单位。
3. 保存原始表格到对象存储。
4. 保存结构化数据到 PostgreSQL JSONB 或专用表。
5. 保存字段元数据。
6. 用户提问时生成查询计划。
7. 对表格做过滤、排序、计算和规则匹配。
8. 输出结果和引用依据。

对于报价表、排班表这种场景，结构化查询比单纯 RAG 更可靠。

### 13.4 RAG 实现

文档类资料采用 RAG：

- 文档解析。
- 分块。
- Embedding。
- pgvector 存储。
- 混合检索，关键词 + 向量。
- 重排。
- 生成答案。
- 引用来源展示。

### 13.5 意图识别 Prompt 要求

意图识别需要输出 JSON，而不是自然语言。

必须识别：

- 用户要做什么。
- 涉及哪个场景。
- 需要哪些资料。
- 已知实体有哪些。
- 缺失哪些关键信息。
- 应该调用哪个 Skill。
- 是否需要创建 UI 卡片，例如便利贴、客户卡、报价卡。

## 17. 主要风险与对策

### 17.1 风险：用户资料格式混乱

对策：

- 提供文件类型识别。
- 提供字段映射 UI。
- 提供样例模板。
- 对不确定字段主动询问用户。

### 17.2 风险：Agent 查表结果不准确

对策：

- 表格类数据结构化存储，不只做向量检索。
- 输出引用来源。
- 对关键业务参数做校验。
- 信息缺失时主动追问。

### 17.3 风险：隐私和剪贴板权限敏感

对策：

- 默认不自动读取剪贴板。
- 用户开启后明确提示范围。
- 支持隐私模式。
- 支持本地清理数据。

### 17.4 风险：桌面提醒不稳定

对策：

- 本地提醒 + 云端提醒双通道。
- Electron 本地定时器负责桌面通知。
- 服务端负责多端推送。
- APP 端作为补充提醒。

### 17.5 风险：产品太泛，用户不知道怎么用

对策：

- MVP 聚焦跨境物流销售和教师排班两个样板场景。
- 首页直接给用户示例问题。
- 引导用户上传对应资料。
- 用“场景助手”替代“Agent/Skill”等技术词。

## 19. 最终产品方向建议

本项目从 B 端转换为 C 端后，最适合的切入点不是“大而全的个人 Agent 平台”，而是：

> 个人职业场景 AI 桌面工作台。

第一版建议重点验证两个样板场景：

1. 跨境物流销售：上传报价表后，一句话完成渠道推荐、报价解释和客户回复。
2. 教师/课程顾问：上传排班表后，一句话查询课程、生成反馈和创建提醒。

同时用“粘贴文字自动识别意图 + 桌面便利贴 + 到期提醒”作为通用高频能力，覆盖更多个人用户场景。

如果这三个能力跑通，后续可以自然扩展到房产经纪人、保险代理人、电商卖家、自由职业者和本地生活商家。
